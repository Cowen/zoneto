## Changes Made

### P0: Fix `dev_appealed` label base rate (`enrich.py`)

**Problem:** `dev_appealed` was assigned using `_label_from_sets(status, _DEV_APPEALED_SET,
_DEV_APPROVED_SET)`, which assigned:
- 1 for appeal statuses
- 0 for explicitly-approved statuses only
- null for everything else (refused, on hold, etc.)

This caused 50/50 class imbalance in training data (1,830 vs 1,795) — a massive
selection bias. Applications closed without appeal via "Refused" or "Closed"
got null labels and were dropped from training, overrepresenting appeals.

**Fix:** Replaced `map_elements` with a Polars expression that:
- Returns null for non-OZ/SA application types (different appeal mechanisms)
- Returns null for null or active statuses
- Returns 1 if status is in `_DEV_APPEALED_SET`
- Returns **0 for all other closed statuses** (including "Refused", "Closed", etc.)

This dramatically increases labeled rows and moves the training base rate toward
the true ~15-25% Toronto appeal rate.

### P0: Restrict survival scoring to OZ+SA only (`score.py`)

**Problem:** `score_all` applied `dev_days_to_decision` survival model to all 26,161
dev applications including CD, SB, PL types — which were never in training data.

**Fix:**
- `score_all`: computes OZ+SA indices, runs survival model only on those rows,
  fills non-OZ/SA rows with null in the `pred_dev_days_to_decision` column
- `score_one`: only runs survival model if `features["application_type"]` is in
  `{"OZ", "SA"}` — otherwise the key is absent from the returned dict

### P1: Raise regressor `production_ready` threshold to R² ≥ 0.10 (`train.py`)

Changed from `r2_mean >= 0.0` to `r2_mean >= 0.10`. `permit_issuance_days` (R²=0.039)
and `coa_days_to_approval` (R²=-0.268) will now correctly be marked `production_ready: false`.

### P1: Skip scoring for non-production-ready models (`score.py`)

Added `_load_production_ready(model_dir)` helper that reads `models/metrics.json`
and returns `{model_name: bool}`. If `metrics.json` is absent, returns `{}` (default
True for all models — backward compatible).

`score_all` now checks this flag before scoring each model. Models marked False are
skipped: their prediction columns are not written to output. This prevents useless
noise columns from appearing in scored parquet.

### P1: Delete stale `dev_applications_approved.joblib` (`models/`)

Deleted `models/dev_applications_approved.joblib` — artifact from a retired model.
Also removed `dev_applications_approved` from the `_MODEL_META` registry in
`analytics/importance.py` so `just importance-all` no longer fails on it.

### P1: Keep ward demographics (no code change)

Per PM decision, ward demographic features (`ward_pct_detached`, `ward_median_income`,
`ward_pop_density`, `ward_pct_renters`) are confirmed valuable via permutation
importance (combined 0.0425 vs `ward_number` alone 0.0109). No changes needed.
