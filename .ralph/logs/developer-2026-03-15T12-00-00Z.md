## Data Investigation: `dev_days_to_decision` (P0 — Blocked)

**Finding:** The `dev_days_to_decision` P0 item cannot be implemented with the current
CKAN dataset. The `dev_applications` CKAN datastore provides these date columns:

- `date_submitted` — only date available

There is no `decision_date`, `close_date`, `status_date`, or any other column that
records when a decision was made. The `status` column captures outcome
(Closed, Under Review, OMB Appeal, etc.) but not the date it changed.

**Consequence:** A time-to-decision regression requires a decision date. Without it,
we cannot compute the training label (`dev_days_to_decision`). The PM's assertion
"data to build it likely exists" was speculative and does not match the CKAN datastore
schema.

**Options documented for next PM review:**
1. Check if the city's `development-applications` portal (individual application pages,
   linked via `application_url`) contains decision dates — would require HTTP scraping,
   not CKAN API.
2. File an FOI request for the internal records database.
3. Accept that time-to-decision cannot be modeled from open data alone; reprioritize.

## Changes Made

### 1. Cap `coa_days_to_approval` at 730 days (`enrich.py`) — P0

**Why:** A 2,992-day outlier (2014 filing closed in 2022) was destabilizing the
`coa_days_to_approval` regression across CV folds. This single point inflated RMSE
and pushed R² to -0.465. Values >730 days (2 years) are almost certainly data errors
or exceptional legacy cases that should not train the model.

**Implementation:** Changed the `coa_days_to_approval` computation in `enrich_coa()`
to require `days <= 730` for the approved case; values beyond 730d become null (excluded
from training like refused/deferred rows).

### 2. Add `production_ready` gate to `train_all()` metrics (`train.py`) — P1

**Why:** PM approved "Gate COA approval/timeline models behind AUC threshold — Protect
user trust." A `coa_approved` model with AUC 0.535 and `coa_days_to_approval` with
R² -0.465 should not be surfaced to users.

**Implementation:** After evaluation in `train_all()`, each model's metrics dict now
includes a `production_ready` bool:
- Classifiers: `roc_auc_mean >= 0.65`
- Regressors: `r2_mean >= 0.0` (negative R² = worse than predicting mean)

This flag is written to `models/metrics.json`. Downstream consumers (scoring UI,
API layer) should check this flag before surfacing model predictions.

**Expected flags after next pipeline run (based on 2026-03-15 metrics):**
- `dev_applications_appealed`: `production_ready = True` (AUC 0.865)
- `coa_approved`: `production_ready = False` (AUC 0.535)
- `coa_days_to_approval`: `production_ready = False` (R² -0.465, expected to improve
  modestly after the 730d outlier cap)
- `permit_issuance_days`: `production_ready = False` (R² 0.039)
